## 3. LOOK AND FEEL: AYURVEDIC, NATURAL, CALM

The site should feel like a trusted, traditional-yet-modern Indian wellness brand: grounded, earthy, quiet, unhurried.

- Generous whitespace, a calm rhythm, a restrained palette; earthy, warm and natural.
- Typography: pair a refined serif for headings (for example **Cormorant Garamond**, **Playfair Display** or **Lora**) with a clean humanist sans for body and UI (for example **Inter**, **Source Sans 3** or **DM Sans**). Load via a single font provider with `font-display: swap`, subset to the weights used. Include a Kannada-capable fallback (e.g. Noto Sans Kannada) only if Kannada text is rendered in live text. The logo's Kannada wordmark is part of the image.
- Define a full type scale (Display, H1–H4, body, small, label, nav, button) with consistent weights, line-heights and letter-spacing.
- Spacing scale: 4, 8, 12, 16, 24, 32, 48, 64, 80, 96, 120 px only. Container max-width about 1200px; content line length capped around 65–72 characters.
- Imagery: use only the three supplied product photos plus the logo. Do not add stock photos or AI-generated imagery. Where a section would otherwise need decoration, use whitespace, a Sand divider or a subtle, low-contrast botanical line motif (one consistent style, used sparingly, and only if it serves a purpose). No random leaf clip-art everywhere.
- Product photos have a dark, studio-style backdrop. Present them in a consistent aspect ratio (4:5) with `object-fit: cover` or `contain` as appropriate, inside a neutral Clouds/Sand frame so the three look like one set. Do not alter the photos beyond cropping and compression.
- Icons: a single consistent line icon set (Lucide), used only where functional (phone, WhatsApp-style chat, mail, Instagram, map pin, menu, close, chevron). No icon in every card.
- Motion: minimal, 150–250ms hover and focus transitions, a simple mobile-menu transition, and nothing else. Respect `prefers-reduced-motion`.

## 5. TECHNICAL REQUIREMENTS

- **Stack:** Next.js (App Router) with TypeScript and plain CSS Modules or Tailwind (pick one, and keep tokens in a single source of truth), or Astro if you prefer a static-first build. Static generation for all pages. Do not add libraries that native features can replace.
- **Data:** a single `products` data file (slug, name, descriptor, image, sections) and a `site` config file (business name, phone, WhatsApp number, email, Instagram URL, city). No contact details hardcoded in components.
- **Reusable components:** Navbar, Footer, Button, ProductCard, Section, Breadcrumb, ContactButtons, ContactForm (if included), Placeholder block. Do not over-componentise simple content.
- **Images:** `next/image` (or equivalent) with explicit width/height, responsive sizes, AVIF/WebP, lazy loading below the fold, descriptive alt text (for example "Amla Turmeric Effervescent Tablet tube, 20 tablets"). Compress the supplied photos.
- **SEO:** unique title and meta description per page, canonical URL, Open Graph and Twitter tags, `sitemap.xml`, `robots.txt`, one H1 per page, and JSON-LD structured data: `LocalBusiness` or `Organization` (name, Bangalore, telephone, email, sameAs Instagram), and `Product` on each product page **without** price, rating or review fields. Use a configurable site URL variable.
- **Accessibility (WCAG 2.2 AA):** semantic landmarks, skip link, heading hierarchy, visible focus rings (use Deep Lake or Forest, 2px), keyboard-operable menu, labelled forms, 44px minimum touch targets, and information never conveyed by colour alone.
- **Performance:** target Lighthouse 95+ on mobile for Performance, Accessibility, Best Practices and SEO. No unused JS or CSS, and no layout shift.
- **Security:** security headers (CSP, X-Content-Type-Options, Referrer-Policy), `rel="noopener noreferrer"` on external links, and no secrets in the client.
- **Responsive:** design mobile, tablet and desktop deliberately. Verify at 320, 375, 390, 414, 768, 1024, 1280, 1440 and 1920 px. No horizontal scroll, no overlap, no cut-off buttons. On mobile, the call and WhatsApp buttons should be easy to reach (a simple sticky bottom bar with the two contact actions is acceptable and encouraged, as it serves the main conversion).
